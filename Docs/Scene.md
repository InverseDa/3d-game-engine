# Scene Runtime

`Scene` owns the persistent identity of entities in a World. Create a scene using `FScene::Create` and assign an explicit UUID with `TryCreateEntity` for each entity that belongs in a scene file. `TryFindEntity` resolves a UUID to its current World handle and `TryGetEntityId` does the inverse. The World owns the entity lifetime and automatically removes its attached identity when an entity is destroyed. Runtime systems can work with `GetWorld()`; a live entity created outside the scene owner has no scene UUID, so saving while it remains in the World returns `MissingEntityIdentity`.

- `CaptureScene` reads a committed Idle World and builds the scene document. It maps typed Mesh and Material handles to persistent asset IDs through the matching registry. Empty entities, local transforms and their parent UUIDs, mesh metadata and camera parameters are saved. The document format and editing examples are covered separately in the scene document format reference.
- `SaveScene` captures and encodes the complete UTF-8 JSON document before calling ContentIO's same-directory atomic replacement. Invalid data, a busy World or a failed file operation returns without replacing an existing save.
- `LoadScene` reads the document within the format limit. `RestoreScene` validates the complete document, creates a candidate World in persistent UUID order and applies parent links in a second pass. Typed resolver callbacks construct missing Mesh and Material assets on demand, and the candidate registry confirms each returned handle and ID. Existing registry entries are reused.
- A failed restore leaves the output scene owner unchanged. The application owns its candidate asset session and should discard it on failure. During a live reload, pass an empty scene owner for the candidate, then publish the candidate World and registry together at a safe frame boundary. Destroy the old scene before its registry. Any assets used by submitted GPU work must stay live until the relevant frames complete.

Failure results identify the failing entity or asset when known. File errors include an `EContentIOResult`. JSON errors include the document diagnostic with source position when available.
